# Lean

Proofs about fastcrypto-threshold's AVSS (`threshold_schnorr::avss`) against a Lean translation of
the Rust code made by [Charon and Aeneas](https://github.com/AeneasVerif/aeneas).

| Path | Contents |
|---|---|
| `Avss/` | The translation of `avss.rs`, generated by `extract.sh`. Code outside `avss.rs` is kept opaque: Lean only sees the signatures of what `avss.rs` calls in other modules and crates. |
| `AvssProofs/` | The proofs. `Result.lean` has the `ok_inv` tactic used by all of them. |
| `extract.sh` | Regenerates `Avss/`. |
| `fix_aeneas_output.py` | Patches Aeneas output that Lean rejects, see below. Called by `extract.sh`. |

To check the proofs, install Lean with `elan` and run `lake build` here. To regenerate `Avss/`
after changing `avss.rs`, get `charon` and `aeneas` from the Aeneas release named in
`extract.sh` and run `CHARON=... AENEAS=... ./extract.sh`.

When Charon translates the crate it sets `cfg(aeneas)`, under which `avss.rs` compiles its
`tracing` logging out, since Aeneas cannot translate `tracing`'s macros.

## What is proved

Each theorem is a contract of `FastcryptoSpecs/Avss/Steps.lean` in fastcrypto-specs, stated about
the generated functions. A Rust `Err` is `ok (Err _)`, and a panic or divergence is a Lean `Result`
other than `ok`. The theorems are about calls that return.

| Theorem | Statement |
|---|---|
| `verify_binds` | `verify_complaint_response(m, j, r) = Ok(v)` ⇒ `v.responder_id = j`. |
| `recover_sound` | `recover(m, vs) = Ok(o)` ⇒ `ValidShares nodes m id o.my_shares`: `share_ids_of(id) = Ok(ids)` and `o.my_shares.verify(m, ids, id) = Ok`. |
| `process_valid` | `process_message(m) = Ok(Valid(o))` ⇒ `ValidShares nodes m id o.my_shares`. |
| `response_verifies` | For receivers with the same `nodes`: `Rⱼ.process_message(m) = Ok(Valid(o))` and `Rⱼ.handle_complaint(m, i, c, o) = Ok(r)` ⇒ `Rᵢ.verify_complaint_response(m, j, r) = Ok(_)`. Assumes `CloneIsId`. |
| `process_invalid_iff` | For receivers with the same `nodes`, `params`, `sid` and `commitment`: `Rᵢ.process_message(m)` is `Err` ⇔ `Rⱼ.process_message(m)` is `Err`. |
| `handle_accepts` | For receivers configured alike and a party `i`: `Rᵢ.process_message(m) = Ok(Complaint(c))` and `Rⱼ.process_message(m) = Ok(Valid(o))` ⇒ `Rⱼ.handle_complaint(m, i, c, o) = Ok(_)`. Assumes `CloneIsId`, `PolyCloneIsId`, `PolyEqRefl` and `RecoveryComplete`. |
| `recover_complete` | `Rᵢ.process_message(m)` is not `Err`, each response in `vs` was returned by `Rᵢ.verify_complaint_response(m, …)`, the responders are distinct, `weight_of(j) = Ok(W(j))` for each responder `j` with `t ≤ Σ W(j) ≤ u16::MAX`, and `share_ids_of(i)` is `Ok` ⇒ `Rᵢ.recover(m, vs) = Ok(_)`. Assumes `PolyCloneIsId` and `InterpolationComplete`. |

## What is assumed

* The translation: Charon, Aeneas and `fix_aeneas_output.py`.
* The opaque functions are arbitrary: nothing is assumed about what they return, except where a
  theorem says so.
* Hypotheses of the theorems that need them, defined in `AvssProofs/`:
  * `CloneIsId`: `SharesForNode::clone` returns an equal value. Its derived code calls the `Clone`
    impls of opaque types.
  * `PolyCloneIsId` and `PolyEqRefl`: `Poly::clone` returns an equal value, and `Poly::eq` of a
    polynomial with itself is `true`.
  * `RecoveryComplete`: the completeness of the recovery proof. For receivers configured alike, a
    complaint that `Rᵢ.create_complaint` makes about a message whose shares `Rᵢ.verify_message`
    rejected is accepted by `Rⱼ.check_recovery_proof`.
  * `InterpolationComplete`: the completeness of share recovery, which depends on the `Nodes`
    functions and polynomial interpolation. For a message that passes `Rᵢ.check_message`, the shares
    of responses that `Rᵢ.verify_complaint_response` returned for distinct responders of total
    weight at least `t` make `SharesForNode::recover` return shares that verify for `Rᵢ`.
* `fix_aeneas_output.py` changes the translation as follows.
  * serde's traits are mutually recursive, which Lean rejects. Their structures are emptied, and
    the derived `Serialize` and `Deserialize` code for the AVSS types becomes axioms. The proofs do
    not use serialization.
  * `core::num::nonzero::ZeroablePrimitive` gets two fields with the same name. One is renamed.
  * An instance that refers to itself (the `BCSSerialized` impl of `SharesForNode`), and any
    function whose body Aeneas could not translate (`check_recovery_proof`, because of the closure
    it passes on), become axioms.
  * Two functions that Aeneas' library does not model yet are defined: `Result::is_err` returns
    `true` exactly for `Err`, and `IntoIterator::into_iter` for `&Vec` returns an iterator over the
    vector's elements.
