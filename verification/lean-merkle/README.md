# Lean proofs for `fastcrypto::merkle`

Proofs about fastcrypto's Merkle tree (`fastcrypto/src/merkle.rs`), against a Lean translation of
the Rust code made by [Charon and Aeneas](https://github.com/AeneasVerif/aeneas). The Rust code
carries no annotations. It is written in a style Aeneas can translate: index loops instead of
iterator chains and closures.

| Path | Contents |
|---|---|
| `Merkle/` | The translation of `merkle.rs`, generated by `extract.sh`. The `hash` module is opaque except for `Digest`. |
| `MerkleProofs/Hash.lean` | `HashModel`, the assumption on the hash function, and what `leaf_hash` and `inner_hash` return under it. |
| `MerkleProofs/Model.lean` | A model of the tree as lists (`levels`, `rootOf`, `pathOf`, `fold`), with completeness and binding for the model. |
| `MerkleProofs/Build.lean`, `Proof.lean`, `Verify.lean` | What the generated `build_from_leaf_hashes`, `root`, `get_proof`, `compute_root` and `verify_proof` return, in terms of the model. |
| `MerkleProofs/Main.lean` | The two theorems below. |
| `extract.sh` | Regenerates `Merkle/`. |
| `fix_aeneas_output.py` | Defines two standard-library functions that Aeneas leaves as axioms. Called by `extract.sh`. |

To check the proofs, install Lean with `elan` and run `lake build` here. To regenerate `Merkle/`
after changing `merkle.rs`, get `charon` and `aeneas` from the Aeneas release named in `extract.sh`
and run `CHARON=... AENEAS=... ./extract.sh`.

## What is proved

The theorems hold for every hash function `T: HashFunction<32>` whose impl satisfies
`HashModel inst H` for some function `H` from byte strings to 32-byte arrays (see below).

| Theorem | Statement |
|---|---|
| `inclusion_complete` | For leaf hashes `hs` with `4 · hs.len() ≤ usize::MAX`, `MerkleTree::build_from_leaf_hashes(hs)` returns a tree `t` and `t.root()` returns a node `root`, both without panicking. For every `i < hs.len()` and every `leaf` with `leaf_hash(leaf) = hs[i]`, `t.get_proof(i)` returns `Ok(p)`, `p.len()` is `depth(hs.len())`, and `p.verify_proof(&root, leaf, i)` returns `Ok(())`. |
| `inclusion_binding` | If `p.verify_proof(&root, leaf, i)` and `p'.verify_proof(&root, leaf', i)` both return `Ok(())` and `p.len() = p'.len()`, then `leaf = leaf'` or `H` has a collision: there are byte strings `x ≠ y` with `H(x) = H(y)`. |

`depth(n)` is the number of levels above the leaves: `0` for `n ≤ 1`, and `depth(⌈n/2⌉) + 1`
otherwise. The proof of `inclusion_binding` is a reduction: it finds the colliding inputs.

`inclusion_binding` needs the two proofs to have the same length. Without it, the theorem is
false: a proof for index `1` of length 1, `[s]`, and one of length 2, `[s', t]`, give the same
root if `s = inner_hash(s', leaf_hash(leaf'))` and `t = leaf_hash(leaf)`. `verify_proof` does not
check the length, so a verifier that knows the number of leaves `n` has to check that
`p.len() = depth(n)`, as `inclusion_complete` says honest proofs have.

On the way, the files prove what each translated function returns:
`build_from_leaf_hashes` returns the concatenated `levels` of the leaf hashes, `root` returns
`rootOf`, `get_proof(i)` returns `pathOf(i)`, `compute_root` returns `None` exactly when the proof
has `usize::BITS` or more levels or the index is not below `2^len`, and otherwise the hash of the
leaf up the path, and `verify_proof` returns `Ok(())` exactly when that hash equals `root`.

## What is assumed

* The translation: Charon, Aeneas and `fix_aeneas_output.py`. The script replaces the axioms that
  Aeneas emits for two `AsRef` impls of the standard library with their definitions:
  `<[T] as AsRef<[T]>>::as_ref` returns its argument, and `<&T as AsRef<U>>::as_ref` calls `T`'s
  `as_ref`.
* `HashModel inst H`, defined in `MerkleProofs/Hash.lean`, about the `HashFunction` impl, which
  Lean sees as a structure of opaque functions: there is a map `absorbed` from hasher states to byte
  strings such that `T::default()` has absorbed nothing, `update(data)` appends
  `data.as_ref()`, and `finalize()` returns `H` of the bytes absorbed. None of the three panics.
* The theorems do not assume anything else about `H`. In particular, collision resistance is not
  assumed; `inclusion_binding` concludes that a collision exists.
* `alloc::fmt::format` and `core::hint::must_use` stay axioms. They are only called in the error
  branch of `get_proof`, and nothing is assumed about them.
* `usize` has 32 or 64 bits, as in Aeneas' library. The theorems hold for both.

## What is not proved

* `build_from_serialized` and `build_from_unserialized` are not translated: Aeneas cannot
  translate their loops over a generic `IntoIterator`. Both push `leaf_hash` of each leaf and call
  `build_from_leaf_hashes`, which is why `inclusion_complete` is stated for leaves whose
  `leaf_hash` is the `i`th leaf hash.
* `is_right_most` is translated but nothing is proved about it, and `MerkleNonInclusionProof` and
  `compute_non_inclusion_proof` are not translated.
