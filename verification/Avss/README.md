# AVSS

`fastcrypto_threshold::threshold_schnorr::avss`: lemmas about the code, and in `Protocol/` the
protocol-level theorems (AVSS, DKG and key rotation) and their link to the code.

| Path | Contents |
|---|---|
| `Generated/` | The translation of `avss.rs`, generated by `extract.sh`. |
| `*.lean` | Lemmas about the generated functions, listed below. `Result.lean` has the `ok_inv` tactic most proofs use. |
| `Protocol/` | Protocol-level theorems and the link to the code. See `Protocol/README.md`. |
| `extract.sh` | Regenerates `Generated/`: get `charon` and `aeneas` from the Aeneas release it names and run `CHARON=... AENEAS=... ./extract.sh`. |
| `fix_aeneas_output.py` | Patches Aeneas output that Lean rejects. Called by `extract.sh`. |

## The translation

`avss.rs` is written in a style Aeneas can translate: loops instead of iterator chains, and its
`tracing` logging compiled out under `cfg(aeneas)`, which Charon sets. The Rust sources carry no
annotations.

`Generated/` contains the functions of `avss.rs` with their bodies. Code in other modules and crates
is opaque: Lean sees only the signatures of what `avss.rs` calls, and of `Poly::eval`. Opaque
functions are arbitrary unless a lemma's hypothesis says otherwise. A Rust `Err` is `ok (Err _)`,
and a panic or a call that does not return is a Lean `Result` other than `ok`.

All proofs trust Charon, Aeneas and `fix_aeneas_output.py`, which changes the translation as
follows:

* serde's traits are mutually recursive, which Lean rejects. Their structures are emptied, and the
  derived `Serialize` and `Deserialize` code of the AVSS types becomes axioms. No proof uses
  serialization.
* `core::num::nonzero::ZeroablePrimitive` gets two fields with the same name. One is renamed.
* An instance that refers to itself (the `BCSSerialized` impl of `SharesForNode`), and any function
  whose body Aeneas could not translate (`check_recovery_proof`, because of its closure), become
  axioms.
* A Rust parameter named `nodes` (of `complete_key_rotation`) shadows the `nodes` module, so the
  generated code refers to that module's functions from the root namespace.
* Two functions that Aeneas' library does not model are defined: `Result::is_err` returns `true`
  exactly for `Err`, and `IntoIterator::into_iter` for `&Vec` returns an iterator over the vector's
  elements.

## Lemmas about the code

`Rᵢ` is a `Receiver` with id `i`; "receivers configured alike" have the same `nodes`, `params`,
`sid` and `commitment`. Lemmas of the form "`f(…) = Ok(x)` ⇒ …" are about calls that return; the
others also say that the call returns.

### What is proved

| Lemma | File | Statement |
|---|---|---|
| `verify_binds` | `VerifyBinds.lean` | `verify_complaint_response(m, j, r) = Ok(v)` ⇒ `v.responder_id = j`. |
| `recover_sound` | `RecoverSound.lean` | `Rᵢ.recover(m, vs) = Ok(o)` ⇒ `ValidShares nodes m i o.my_shares`: `share_ids_of(i) = Ok(ids)` and `o.my_shares.verify(m, ids, i) = Ok`. |
| `process_valid` | `ProcessValid.lean` | `Rᵢ.process_message(m) = Ok(Valid(o))` ⇒ `ValidShares nodes m i o.my_shares`. |
| `process_invalid_iff` | `ProcessInvalidIff.lean` | For receivers configured alike: `Rᵢ.process_message(m)` is `Err` ⇔ `Rⱼ.process_message(m)` is `Err`. |
| `handle_accepts` | `HandleAccepts.lean` | For receivers configured alike: `Rᵢ.process_message(m) = Ok(Complaint(c))` and `Rⱼ.process_message(m) = Ok(Valid(o))` ⇒ `Rⱼ.handle_complaint(m, i, c, o) = Ok(_)`. |
| `response_verifies` | `ResponseVerifies.lean` | For receivers with the same `nodes`: `Rⱼ.process_message(m) = Ok(Valid(o))` and `Rⱼ.handle_complaint(m, i, c, o) = Ok(r)` ⇒ `Rᵢ.verify_complaint_response(m, j, r) = Ok(_)`. |
| `recover_complete` | `RecoverComplete.lean` | `Rᵢ.process_message(m)` is not `Err`, each response in `vs` was returned by `Rᵢ.verify_complaint_response(m, …)`, the responders are distinct, `weight_of(j) = Ok(W(j))` with `t ≤ Σ W(j) ≤ u16::MAX`, and `share_ids_of(i)` is `Ok` ⇒ `Rᵢ.recover(m, vs)` returns `Ok(_)`. |
| `feldman_binding` | `FeldmanBinding.lean` | `Rᵢ.process_message(m)` is not `Err` ⇒ there is a scalar polynomial `p` with `p.degree() < t` such that `sh.verify(m, ids, j) = Ok` ⇒ `sh.shares` and `ids` have the same length and the `n`-th share's value is `p.eval(ids[n]).value`. |
| `recover_commitment` | `OutputCommitment.lean` | With `Poly::clone` the identity, `Rᵢ.recover(m, vs) = Ok(o)` ⇒ `o.feldman_commitment = m.feldman_commitment`. |
| `verify_complete` | `VerifyComplete.lean` | `sh.verify(m, ids, j) = Ok` when the shares' indices are `ids`, in order, and each share passes `verify_share`. |
| `complete_key_rotation_ok` | `KeyRotation.lean` | `complete_key_rotation(t, i, nodes, outputs) = Ok(dk)` ⇒ there are `t` outputs, and with `(c, λ)` the Lagrange coefficients for their indices, `dk`'s share at each `k` in `share_ids_of(i)` is `Σᵤ Vᵤ(k)·λᵤ·c`, where `Vᵤ(k)` is output `u`'s share at `k`. |
| `complete_key_rotation_commitment` | `RotationCommitment.lean` | `complete_key_rotation(t, i, nodes, outputs) = Ok(dk)` and `dk.commitment_for_index(k) = Some(e)` ⇒ with `(c, λ)` the Lagrange coefficients for the outputs' indices, `e.value = G::generator() * Σᵤ yᵤ·λᵤ·c`, where `outputs[u].feldman_commitment.eval(k) = G::generator() * yᵤ`. |

Smaller lemmas on the way: the loops of `recover` and `all_distinct` (`Loops.lean`) and of
`complete_key_rotation` (`KeyRotation.lean`, `RotationCommitment.lean`), `commitment_for_index_some`, and
`check_message_commitment`, `check_message_degree` and `process_message_check`, which say what a
message that passes `check_message` satisfies, and `verify_message_commitment`: an output of
`verify_message` carries the message's commitment. `Result.lean` has the `ok_inv` tactic most proofs
use.

### What is assumed

Besides the translation, these hypotheses, each a `def` in the file of the
lemma that needs it. They are about code outside `avss.rs`, which the translation keeps opaque.

| Hypothesis | Statement | Lemmas |
|---|---|---|
| `CloneIsId` | `SharesForNode::clone` returns an equal value (it calls the `Clone` impls of opaque types). | `response_verifies`, `handle_accepts` |
| `PolyCloneIsId` | `Poly::clone` returns an equal value. | `handle_accepts`, `recover_complete`, `recover_commitment`, `complete_key_rotation_commitment` |
| `PolyEqRefl` | `Poly::eq` of a polynomial with itself is `true`. | `handle_accepts` |
| `RecoveryComplete` | The recovery proof is complete: for receivers configured alike, a complaint `Rᵢ.create_complaint` makes about a message whose shares `Rᵢ.verify_message` rejected is accepted by `Rⱼ.check_recovery_proof`. | `handle_accepts` |
| `InterpolationComplete` | For a message that passes `Rᵢ.check_message`, the shares of responses `Rᵢ.verify_complaint_response` returned for distinct responders of total weight `≥ t` make `SharesForNode::recover` return shares that verify for `Rᵢ`. This rests on the `Nodes` functions and on interpolation. | `recover_complete` |
| `CommitmentBinding` | Feldman commitments over secp256k1 bind: a commitment of degree `d` commits to a scalar polynomial `p` of degree `≤ d`, and a share passes `verify_share` only if its value is `p.eval` at its index. | `feldman_binding` |
| `NonZeroGetInj` | Two `NonZeroU16`s with the same `get()` are equal (Lean sees `NonZero` as opaque). | `feldman_binding`, `complete_key_rotation_ok`, `complete_key_rotation_commitment` |
| `ScalarHom` | A map `f` from secp256k1 scalars to a field takes the `zero`, `+=` and both forms of `*` that `complete_key_rotation` uses to the field's. | `complete_key_rotation_ok`, `complete_key_rotation_commitment` |
| `MsmEval` | `Poly::multi_scalar_mul(ps, ss) = Ok(q)` ⇒ if each `ps[j].eval(k)` returns `G::generator() * yⱼ`, `q.eval(k)` returns `G::generator() * Σⱼ yⱼ·ss[j]`. | `complete_key_rotation_commitment` |
| `EvalRangeSound` | Each entry `e` of `p.eval_range(m).to_vec()` is `p.eval(e.index)`. | `complete_key_rotation_commitment` |
